# عدة التاجر الذكي

تطبيق عربي لإدارة المتاجر على Windows وAndroid. المشروع ما زال قيد التطوير، وليس إصدارًا تجاريًا جاهزًا. لا تستخدم بيانات متجر حقيقية قبل استكمال الأمان والمزامنة والاختبارات الميدانية.

## حالة الفرع الحالية

الفرع `feature/multi-user-cloud` يحتوي على نواة محلية تعمل باستخدام Flutter وSQLite. يدعم التطبيق حاليًا إدارة المنتجات والمخزون والمبيعات والمشتريات والموردين والعملاء والمصروفات والفروع والمخازن، مع عمليات محلية واختبارات آلية.

آخر تحقق مؤكد على الالتزام `f83ba61040db3323f7133aac968fadf1f6a03d65`:
- Flutter Analyze: ناجح بلا أخطاء.
- الاختبارات: 102 اختبار ناجح.
- بناء Android debug: ناجح.
- بناء Windows x64: ناجح.

هذه النتائج تثبت نجاح التحليل والاختبارات والبناء داخل GitHub Actions فقط؛ لا تثبت التشغيل على أجهزة فعلية أو الجاهزية التجارية.

أحدث تحقق Flutter في التشغيل `41751141214`: Analyze بلا مشاكل و102 اختبار ناجح. بناء Windows release وAndroid debug split-per-ABI نجحا، ورُفعت artifacts باسم `smart-merchant-suite-windows-x64` و`smart-merchant-suite-android-debug-apks` مع ملفات SHA-256 ومعلومات البناء. رابط التشغيل والتحميل: https://github.com/ashraf18275/smart-merchant-suite/actions/runs/41751141214

## الوظائف المحلية الموجودة

- واجهة عربية RTL ولوحة أقسام.
- إدارة المنتجات والتصنيفات ووحدات القياس.
- فروع ومخازن متعددة محليًا، مع أرصدة منفصلة لكل مخزن.
- تسوية المخزون والتحويل بين المخازن مع تسجيل الحركات داخل معاملات.
- نقطة بيع متعددة الأصناف، واختيار المخزن، وحفظ الفاتورة والبنود وتحديث المخزون ذريًا.
- ربط البيع بعميل، وتسجيل الرصيد المستحق والمدفوعات الجزئية في دفتر حساب العميل.
- إدارة الموردين وإدخال فاتورة شراء متعددة الأصناف واستلام المخزون.
- تحديث متوسط تكلفة المنتج المرجح عند الاستلام، وتسجيل التزامات المورد والمدفوعات.
- تسجيل المصروفات وملخص مالي أولي.
- تصدير CSV.
- إنشاء نسخة SQLite احتياطية متسقة باستخدام `VACUUM INTO` والتحقق من الملف.
- استعادة نسخ محلية من مخططات الإصدارات 3 إلى 9 مع تحويلات توافقية، والتحقق من العلاقات، وتنفيذ الاستبدال داخل معاملة.
- أساس Supabase للحسابات والصلاحيات، مع فروع ومخازن سحابية وأرصدة منفصلة لكل مخزن وعمليات بيع/تسوية مرتبطة بالمخزن. هذه البنية ليست تكاملًا سحابيًا متصلًا بالتطبيق بعد.
- منع الحذف المباشر لمصروفات السحابة، وقصر تغييرات العضويات والصلاحيات وسجل التدقيق على الخدمات الخادمية الموثوقة.
- إجراء خادمي ذري لتحديث صلاحيات الأعضاء مع سجل تدقيق، ومنع المدير المفوض من تصعيد صلاحياته.
- تعويض فشل إنشاء العضو بطريقة fail-closed مع تعطيل العضوية عند فشل حذفها.
- اختبارات PostgreSQL أولية لعزل الأنشطة والصلاحيات والأعضاء غير النشطين، ومنع التعديل المالي غير الموثق، واختبار رفض إعادة استخدام معرف العملية مع حمولة مختلفة.

## ما لم يكتمل بعد

- تسجيل الدخول الفعلي من التطبيق، وإضافة المستخدمين وإدارة كلمات المرور من داخله.
- واجهة قائمة الصلاحيات المرنة وتطبيق التفويض على كل عملية داخل التطبيق والخادم.
- استكمال اختبارات سياسات RLS وعزل الأنشطة والفروع والأدوار، والتكامل الكامل مع Supabase من التطبيق.
- مزامنة فعلية بين الأجهزة، وطابور عمليات offline/outbox، ومعالجة التعارضات وإعادة المحاولة.
- متابعة المالك لحركة المتجر عن بُعد من جهاز آخر.
- استكمال دورة المرتجعات والإلغاء الموثق.
- ورديات الصندوق والإغلاق والمطابقة.
- باركود متكامل، وتعليق واستكمال سلة البيع، والطباعة والإيصالات.
- تقارير تشغيلية ومالية مكتملة حسب الفترة والفرع والمستخدم، ومطابقتها مع السجلات.
- إعداد العملة لكل نشاط، واختبار الدقة والتقريب عبر جميع المسارات.
- التحقق من النسخ والاستعادة على جهاز آخر، واختبار يوم عمل كامل على Windows وAndroid.
- باقات المنتج المجانية والمدفوعة، حدودها، والفوترة أو الاشتراك التجاري.
- مراجعة أمنية خارجية، وسياسات الخصوصية والاحتفاظ بالبيانات قبل الإطلاق.
- مسارات خادمية معتمدة لعكس المصروفات وإدارة العضويات والصلاحيات مع سجل تدقيق كامل.

## قواعد المنتج المعتمدة

- لا يحسب التطبيق ضريبة ولا ينشئ فاتورة ضريبية. يمكن إدخال مبلغ يراد تسجيله يدويًا كمصروف عادي.
- تحفظ الأموال بوحدات صحيحة من العملة الصغرى.
- المتوسط المرجح المتحرك هو سياسة تكلفة المخزون المعتمدة.
- يمنع المخزون السالب افتراضيًا.
- لا ينشأ رصيد بيع آجل دون عميل.
- لا يمحى أثر مالي أو مخزني بصمت؛ يجب أن يكون العكس موثقًا.
- لا حد ثابت داخل المنتج لعدد المستخدمين، والصلاحيات يفترض أن تكون قابلة للتخصيص؛ لم يكتمل تنفيذها بعد.
- لا تدّعِ وجود مزامنة أو مراقبة عن بُعد قبل تنفيذها واختبارها فعليًا.

## آخر تحقق سحابي

- تشغيل Supabase/PostgreSQL CI رقم `41751141019` ناجح، بما في ذلك تطبيق الهجرات واختبارات الأمان والبيع الكسري وترحيل بيانات قديمة بوحدة القطعة إلى وحدة الألف: https://github.com/ashraf18275/smart-merchant-suite/actions/runs/41751141019
- فحص Deno Edge Functions ناجح.
- تشمل الاختبارات أعضاء نشطين وغير نشطين، وصلاحية عرض دون صلاحية البيع، ومنع الحذف المالي المباشر، وحماية تعديلات العضويات والصلاحيات وسجل التدقيق، واختبار تحديث الصلاحيات المفوضة ومنع تصعيدها، وربط معرف العملية ببصمة الحمولة لمنع قبول إعادة إرسال مختلفة.
- لا تمثل هذه الاختبارات مراجعة أمنية شاملة أو جاهزية تجارية. اختُبر تحويل بيانات تاريخية في قاعدة اختبار منفصلة؛ لم تطبق الهجرات على قاعدة إنتاجية. لا توجد مزامنة Flutter فعلية بعد.
