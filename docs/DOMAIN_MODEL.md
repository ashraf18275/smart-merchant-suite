# نموذج المجال والبيانات — عدة التاجر الذكي

**الغرض:** تحديد الكيانات والعلاقات والقيود قبل إعادة بناء التخزين. هذا تصميم مقترح معتمد للمرحلة، وليس مخطط قاعدة مطبقًا.

## حدود البيانات
- **النشاط التجاري (Business):** وحدة الملكية والعزل والعملة والمنطقة الزمنية والسياسات.
- **الفرع (Branch):** موقع تابع لنشاط؛ له حالة وإعدادات تشغيلية محدودة.
- **المخزن (Warehouse):** موقع رصيد داخل فرع. الرصيد لا يحفظ في بطاقة المنتج.
- **العضوية (Membership):** ربط مستخدم بنشاط، مع حالة نشطة ونطاق الفروع المسموح بها.
- **الصلاحية (Permission Grant):** مفتاح ثابت لفعل واحد على نطاق نشاط أو فرع. المالك الإداري كيان مميز لا ينشأ عبر صلاحية عادية.
- **سجل التدقيق (Audit Event):** الفاعل والوقت والنطاق والفعل والكيان ومرجع العملية؛ يحفظ التغييرات الحساسة دون أسرار.

## الكتالوج والمخزون
- **Product:** تعريف الصنف التجاري على مستوى النشاط، مع SKU وحالة وأسماء.
- **Product Variant:** تفاصيل خيار قابل للبيع عند الحاجة، مثل الحجم أو اللون، ومعرف/باركود مستقل.
- **Category وUnit:** تصنيفات ووحدات قابلة للتهيئة؛ التحويلات بين الوحدات معرفة صراحة.
- **Inventory Balance:** كمية وتكلفة مرجحة لكل منتج/متغير ومخزن. يتغير داخل معاملات الحركات فقط.
- **Inventory Movement:** سجل غير قابل للمحو الصامت؛ نوع الحركة، فرق الكمية، التكلفة، المخزن، السبب، الفاعل، المصدر ومعرف العملية.
- **Stock Count / Transfer / Receipt:** مستندات الجرد والتحويل والاستلام التي تولد الحركات؛ لا تحدث الرصيد مباشرة من الواجهة.

## البيع والمال
- **Sale:** رقم محلي/عام فريد، الفرع، الكاشير، الحالة، التوقيت، إجمالي الخصم، الإجمالي الصافي، معرف العملية.
- **Sale Item:** المنتج والكمية وسعر الوحدة والخصم وتكلفة الوحدة الملتقطة عند البيع. لا يعتمد الربح لاحقًا على تكلفة بطاقة المنتج المتغيرة.
- **Payment:** عملية مالية مرتبطة بفاتورة أو استرداد، مع وسيلة دفع وقيمة ومرجع. تسمح الفاتورة بعدة دفعات.
- **Customer / Receivable:** العميل اختياري للمبيعات النقدية؛ مطلوب عند وجود رصيد آجل. الرصيد يحسب من الفواتير والدفعات والمرتجعات ولا يعدل منفردًا.
- **Return / Return Item:** مرجع إلزامي إلى الفاتورة وبندها، كمية قابلة للرد، حالة الصنف، اعتماد، مبلغ، ومصير المخزون.
- **Expense:** مبلغ ووصف وتصنيف ووقت وفرع وفاعل ومرفق اختياري. لا يحتوي حساب ضريبة؛ المبالغ التي يدخلها المستخدم كمصروف تحفظ كتلك.
- **Cash Shift / Cash Movement:** وردية كاشير مع رصيد افتتاحي وحركات نقدية وإغلاق ومطابقة.

## الشراء والتكلفة
- **Supplier / Purchase Order / Goods Receipt / Supplier Invoice / Supplier Payment:** تحفظ الطلب والاستلام والفاتورة والسداد ككيانات منفصلة.
- تحدث التكلفة المرجحة عند الاستلام الفعلي فقط. لكل منتج/مخزن: متوسط جديد = (قيمة الرصيد قبل الاستلام + قيمة الكمية المستلمة) ÷ إجمالي الكمية بعد الاستلام. تحفظ القيمة بدقة صحيحة وتطبق قاعدة التقريب المعتمدة.
- مرتجع المورد يعكس الكمية والقيمة مع مرجع الاستلام. لا يعاد حساب تكلفة مبيعات سابقة.

## الهوية والصلاحيات
- المستخدم يمكن أن ينتمي إلى أكثر من نشاط؛ لكل نشاط عضوية مستقلة.
- لا توجد أدوار وظيفية ثابتة. قائمة صلاحيات مفصلة يمكن تحديدها كاملة ثم استثناء صلاحيات. يمكن توفير قوالب اختيارية قابلة للتعديل، ولا تصبح مصدر التفويض.
- الصلاحيات تشمل الإجراء والنطاق: منتجات، مخزون، بيع، خصم، إلغاء، مرتجع/اعتماد، مصروفات، شراء، صندوق، تقارير، تصدير، إعدادات، أعضاء، وتدقيق.
- لا يعتمد الخادم على قيمة صلاحية مرسلة من العميل؛ يقرأ المنح المخزنة ويطبقها عند كل طلب حساس.
- تعطيل العضو يمنع استخدامه فورًا مع حفظ أثره التاريخي.

## العمل المحلي والمزامنة
- تخزن قاعدة الجهاز معرفات النشاط/الفرع والمخزن ومعرفات سجلات قابلة للمزامنة.
- **Outbox Operation:** معرف فريد، نوع العملية، الحمولة اللازمة، وقت الإنشاء، حالة المحاولة، إصدار المخطط. تخزن الحمولات بأقل بيانات لازمة، وتحمي محليًا حسب حساسية الجهاز.
- **Server Operation Receipt:** يسجل معرف العملية ونتيجتها لتكون إعادة المحاولة آمنة.
- **Conflict Record:** يسجل التعارض ويعرض حلًا قابلًا للمراجعة. لا تطبق last-write-wins على المبيعات أو المخزون.
- عمليات البيع والاستلام والتحويل والمرتجع ذرية على الخادم مع قفل/تسلسل مناسب، وتنتج أثر تدقيق.

## قيود النزاهة
1. كل سجل خاص بنشاط يحمل business_id، وكل سجل مكاني يحمل branch_id و/أو warehouse_id وفق ملكيته.
2. المفاتيح الأجنبية المركبة تمنع ربط سجل بفرع أو نشاط آخر.
3. كل حركة مخزون لها مستند مصدر أو سبب معتمد وفاعل.
4. لا يحذف مستند مالي أو حركة مخزون؛ يعكس الأثر بحركة موثقة.
5. كل الأموال بوحدات صحيحة وبعملة النشاط. لا تجمع عملات مختلفة في تقرير واحد.
6. عملية البيع الواحدة لا يمكن تنفيذها مرتين حتى عند انقطاع الاتصال وإعادة المحاولة.
7. الاستعادة تفحص إصدار المخطط وقيود العلاقات وسلامة الملف قبل استبدال قاعدة المستخدم.
