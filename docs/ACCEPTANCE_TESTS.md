# معايير القبول — عدة التاجر الذكي

**الحالة:** هذه معايير قبول على مستوى التطبيق، ومعظمها لم يُختبر end-to-end بعد. توجد اختبارات وحدة وواجهة لبعض وظائف المنتجات والمخزون؛ لا تُعد هذه الاختبارات دليلًا على اكتمال سيناريوهات البيع أو النسخ الاحتياطي أو المزامنة.

| ID | الاختبار | معيار القبول |
|---|---|---|
| AT-01 | العمل دون إنترنت | إنشاء منتج وبيع ومصروف دون اتصال، ثم إغلاق التطبيق وإعادة فتحه مع بقاء البيانات. |
| AT-02 | إجمالي الفاتورة | سعر 100.00 × كمية 2 − خصم 10.00 = إجمالي 190.00 قبل الضرائب الإضافية. |
| AT-03 | حساب الربح | مبيعات صافية 500.00 − تكلفة بضاعة مباعة 320.00 = مجمل ربح 180.00؛ بعد مصروفات 40.00 يصبح صافي الربح التشغيلي 140.00. |
| AT-04 | تحديث المخزون | بيع كمية 2 من رصيد 10 ينتج رصيدًا قدره 8. تحفظ الفاتورة والحركة معًا أو لا يُحفظ أي منهما عند فشل المعاملة. |
| AT-05 | منع المخزون السالب | إذا كان إعداد منع المخزون السالب مفعّلًا، يُرفض بيع كمية أكبر من المتاح برسالة واضحة. |
| AT-06 | المرتجعات | ينشئ المرتجع حركة عكسية موثقة ويحدّث الرصيد والتقرير دون حذف الفاتورة الأصلية. |
| AT-07 | تقارير الفترات | يعرض التقرير العمليات الواقعة ضمن تاريخ البداية والنهاية وفق المنطقة الزمنية للنشاط. |
| AT-08 | النسخ والاستعادة | إنشاء نسخة احتياطية واستعادتها في بيئة اختبار؛ تتطابق أعداد المنتجات والفواتير والأرصدة. |
| AT-09 | تكرار المزامنة | إرسال العملية نفسها مرتين لا ينشئ فاتورة أو حركة مخزون مكررة. |
| AT-10 | تعارض جهازين | لا تُفقد تعديلات السجل نفسه بصمت؛ تُطبق سياسة موثقة أو يُطلب حل التعارض. |
| AT-11 | انتهاء الترخيص | لا يمنع الترخيص المنتهي الوصول إلى البيانات الأساسية أو تصديرها أو استعادة النسخة الاحتياطية. |
| AT-12 | الصلاحيات | لا يستطيع المستخدم غير المخوّل تنفيذ عملية محظورة. |
| AT-13 | العربية وRTL | تظهر النصوص العربية واتجاهها وعناصر الواجهة دون تداخل على الكمبيوتر وأندرويد المستهدفين. |
| AT-14 | الانقطاع أثناء البيع | لا تترك المقاطعة أو إغلاق التطبيق فاتورة جزئية أو مخزونًا غير متسق. |
| AT-15 | دقة الأموال | لا تتسبب الحسابات المتكررة أو الخصومات في أخطاء تقريب غير مقبولة؛ تُستخدم طريقة تخزين دقيقة موثقة. |
| AT-16 | البحث | يعثر البحث عن منتج باستخدام الاسم أو الرمز/الباركود عند توفره، ويعرض نتائج صحيحة. |

## تغطية آلية موجودة حاليًا

تغطي الاختبارات الحالية بعضًا من هذه السلوكيات على مستوى المستودع والواجهة:
- إضافة المنتج والتحقق من البيانات الأساسية.
- البحث بالاسم أو الكود.
- تعديل تفاصيل المنتج مع الحفاظ على كمية المخزون.
- تسجيل تغيير المخزون وسبب الحركة.
- رفض المخزون السالب دون تسجيل حركة غير صحيحة.
- إيقاف المنتج وإعادة تفعيله دون حذف سجل الحركات، ومنع حركات المخزون أثناء الإيقاف.

هذه تغطية جزئية وليست بديلًا عن تنفيذ سيناريوهات القبول الكاملة على أجهزة فعلية. تظل حالات البيع والفواتير والربح والنسخ الاحتياطي والمزامنة مخططة حتى تنفيذها واختبارها.

## سجل التنفيذ المطلوب
لكل اختبار، سجّل:
- تاريخ التنفيذ والنسخة/الالتزام (commit).
- الجهاز ونظام التشغيل.
- خطوات التنفيذ والبيانات التجريبية.
- النتيجة المتوقعة والنتيجة الفعلية.
- PASS / FAIL / BLOCKED.
- رابط العطل إن فشل الاختبار.

لا تضع PASS قبل تنفيذ الاختبار فعليًا.
