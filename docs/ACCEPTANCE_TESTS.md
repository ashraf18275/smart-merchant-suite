# معايير القبول — عدة التاجر الذكي

**الحالة:** مواصفات اختبار للمنتج. تضاف اختبارات مصدرية مع كل مرحلة، لكن تظل الحالة NOT RUN حتى يظهر تشغيل ناجح موثق على الالتزام الحالي. لا تستنتج النجاح من وجود شاشة أو دالة.

## المال ونقطة البيع
| ID | السيناريو | معيار القبول |
|---|---|---|
| POS-01 | فاتورة متعددة الأصناف | اختيار الأصناف من قائمة/بحث، وإظهار الكمية وسعر الوحدة وإجمالي البند؛ تعديل الكمية والسعر وإضافة وحذف البنود، وحفظ البنود والمخزون بذرية؛ لا ضريبة آلية. |\n| POS-10 | سعر بيع متغير | يسمح بتعديل سعر الوحدة في الفاتورة دون تغيير السعر المقترح في بطاقة الصنف. |\n| POS-11 | بيع خدمة | يمكن إضافة خدمة إلى الفاتورة دون خصم مخزون أو إنشاء حركة مخزون. |\n| POS-12 | عميل الفاتورة | اختيار عميل موجود أو ترك الفاتورة نقدية بلا عميل؛ يمنع الرصيد الآجل دون عميل. |
| POS-02 | وسائل دفع متعددة | مجموع الدفعات لا يتجاوز الصافي، وتتطابق الفاتورة مع سجل الدفع. |
| POS-03 | بيع جزئي | يعرض المتبقي ويربط الدين بعميل؛ يرفض دينًا بلا عميل. |
| POS-04 | إعادة إرسال | إرسال المعرف نفسه مرتين ينتج فاتورة وحركات مرة واحدة. |
| POS-05 | انقطاع أثناء الحفظ | تعاد العملية بأمان ولا تظهر فاتورة جزئية أو خصم مخزون مكرر. |
| POS-06 | خصم | لا يطبق خصمًا يتطلب اعتمادًا دون الصلاحية؛ يسجل الفاعل والقيمة السابقة والجديدة. |
| POS-07 | مرتجع جزئي/كلي | لا يتجاوز الكمية القابلة للرد؛ يرتبط بالأصل ويحسب المبلغ من قيمة البيع الأصلية. |
| POS-08 | حالة الصنف المرتجع | الصنف الصالح فقط يعود للمخزون؛ التالف يسجل بمصير منفصل. |
| POS-09 | إلغاء | لا يحذف فاتورة؛ ينشئ أثرًا عكسيًا موثقًا ومقيد الصلاحية. |

## المنتجات والمخزون والشراء
| ID | السيناريو | معيار القبول |
|---|---|---|
| INV-01 | بيع من مخزن | ينقص رصيد المخزن المحدد فقط ولا يصبح أي رصيد سالبًا افتراضيًا. |
| INV-02 | استلام شراء | يزيد الكمية وينشئ طبقة تكلفة مستقلة بسعر الشراء الفعلي داخل معاملة واحدة بعد الاستلام. |\n| INV-06 | قيمة المخزون | تساوي مجموع تكلفة الكميات المتبقية في دفعات الشراء، حتى مع اختلاف أسعار الدفعات. |\n| INV-07 | صرف الدفعات | يخصم البيع من أقدم دفعة متاحة (FIFO) ويحفظ تكلفة الصرف في بند الفاتورة. |\n| CAT-01 | تصنيف المنتج | يحفظ التصنيف المختار ويرجع ظاهرًا عند إعادة فتح المنتج وتعديله. |\n| CAT-02 | وحدات القياس | تتوفر وحدات شائعة افتراضيًا مع إمكانية إضافة وحدة مخصصة، وتطبق قواعد الكسور حسب الوحدة. |\n| CAT-03 | إعادة استخدام اسم صنف | تظهر اقتراحات الأصناف الموجودة أثناء الكتابة؛ إعادة الشراء لا تنشئ صنفًا مكررًا بسبب اختلاف التكلفة. |\n| CAT-04 | العملاء والموردون | يظهر كل منهما قسمًا مستقلًا مع ملف وسجل حركات وكشف حساب مستقل. |
| INV-03 | تحويل فرعي | تحفظ حركة خروج ودخول مرتبطة؛ مجموع الكمية محفوظ. |
| INV-04 | جرد وتسوية | يسجل الكمية الفعلية والفرق والسبب والفاعل؛ لا يمحو التاريخ. |
| INV-05 | ترحيل قاعدة قديمة | يحفظ السجلات والعلاقات والأرصدة أو يفشل دون تغيير القاعدة الأصلية. |

## الصلاحيات والفروع
| ID | السيناريو | معيار القبول |
|---|---|---|
| SEC-01 | قائمة صلاحيات | يعرض كل صلاحية بوصف عربي، ويدعم تحديد الكل وإلغاء صلاحيات منفردة. |
| SEC-02 | تحقق الخادم | رفض الإجراء غير الممنوح حتى عند استدعاء API مباشرة. |
| SEC-03 | مستخدم معطل | تمنع جلساته وطلباته الجديدة، مع بقاء سجله التاريخي. |
| SEC-04 | عزل نشاط | يمنع قراءة أو تعديل أي سجل من نشاط آخر. |
| SEC-05 | عزل فرع | لا يسمح فرع لمستخدم دون تفويض؛ تظل التقارير المجمعة مخصصة للصلاحية. |
| SEC-06 | سجل التدقيق | يسجل الفاعل والوقت والإجراء والكيان والتغير الحساس دون بيانات سرية. |

## المال والتقارير والبيانات
| ID | السيناريو | معيار القبول |
|---|---|---|
| FIN-01 | عملة النشاط | كل تقرير يعرض رمز العملة ودقتها، ولا يجمع نشاطين بعملتين. |
| FIN-02 | مبلغ يدوي متعلق بالضريبة | لا يحسب النظام ضريبة؛ يسجل المستخدم المبلغ كمصروف عادي بوصفه. |
| FIN-03 | تكلفة الربح | تستخدم تكلفة البضاعة الملتقطة في الفاتورة حسب دفعات الشراء الفعلية المصروفة وفق FIFO وقت البيع. |
| FIN-04 | تقرير ربح معلوم | يطابق صافي المبيعات − تكلفة المباعة − المصروفات لبيانات اختبار معلومة. |
| DATA-01 | تصدير عربي | ملف CSV صالح بترميز UTF-8، واقتباس صحيح، دون تجاوز الصلاحية. |
| DATA-02 | نسخ واستعادة | تستعاد نسخة على جهاز اختبار آخر بعد فحص السلامة والمخطط والعلاقات. |
| DATA-03 | ترحيل | كل ترحيل قابل لإعادة الإنتاج والاختبار مع نسخة قديمة ونسخة فارغة. |

## أجهزة واستخدام يومي
| ID | السيناريو | معيار القبول |
|---|---|---|
| UX-01 | RTL | شاشات البيع والمخزون والتقارير لا تتداخل على Android وWindows المستهدفين. |
| DEV-01 | قارئ باركود | يضيف الصنف الصحيح من الكود دون إدخال يدوي متكرر. |
| DEV-02 | فشل الطابعة | لا يفقد البيع؛ تظهر حالة فشل الطباعة وإعادة المحاولة. |
| OPS-01 | يوم تشغيل كامل | افتتاح وردية، بيع، دفع، مرتجع، مصروف، إغلاق ومطابقة تقرير دون تناقض. |
| SYNC-01 | جهازان وتعارض | تحفظ المزامنة إعادة المحاولة والتعارض وفق سياسة ظاهرة ولا تستبدل المخزون بصمت. |

لكل تشغيل سجل الالتزام والتاريخ والجهاز ونظام التشغيل والخطوات والبيانات المتوقعة والفعلية والحالة ورابط العطل.
