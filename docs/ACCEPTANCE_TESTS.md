# معايير القبول — عدة التاجر الذكي

**الحالة:** هذه معايير مستهدفة. لا يسجل PASS إلا بعد تنفيذ الاختبار في البيئة المحددة؛ اختبارات الوحدة لا تثبت اكتمال السيناريو end-to-end.

| ID | الاختبار | معيار القبول |
|---|---|---|
| AT-01 | العمل دون إنترنت | إنشاء بيانات محلية وإعادة فتح التطبيق مع بقائها. |
| AT-02 | إجمالي الفاتورة | 100.00 × 2 − خصم 10.00 = 190.00؛ لا ضريبة آلية. |
| AT-03 | الربح | مبيعات 500 − تكلفة مباعة 320 − مصروف 40 = صافي تشغيلي 140. |
| AT-04 | تحديث المخزون | بيع 2 من 10 يجعل الرصيد 8؛ تحفظ الفاتورة والحركة معًا أو لا تحفظان. |
| AT-05 | المخزون السالب | يرفض البيع فوق المتاح؛ المنع هو الافتراضي. |
| AT-06 | المرتجع | يرتبط بالأصل ويسجل الحالة والحركة العكسية دون حذف الفاتورة. |
| AT-07 | الفترات | تطبق حدود التاريخ والمنطقة الزمنية للنشاط. |
| AT-08 | النسخ والاستعادة | تستعاد نسخة اختبارية وتطابق السجلات والأرصدة. |
| AT-09 | تكرار المزامنة | إعادة العملية ذات المعرف نفسه لا تنشئ سجلات مكررة. |
| AT-10 | التعارض | لا تضيع تغييرات المبيعات أو المخزون بصمت. |
| AT-11 | انتهاء الترخيص | تظل البيانات متاحة للتصدير والاستعادة. |
| AT-12 | الصلاحيات | يمنع كل إجراء غير ممنوح، مع وصف عربي واضح للصلاحيات. |
| AT-13 | RTL | الواجهة بلا تداخل على الأجهزة المستهدفة. |
| AT-14 | انقطاع البيع | لا تنتج فاتورة جزئية أو بيانات مخزون غير متسقة. |
| AT-15 | دقة الأموال | تخزين دقيق واختبارات تقريب موثقة. |
| AT-16 | البحث | البحث بالاسم أو الرمز يعرض النتائج الصحيحة. |
| AT-17 | مبلغ ضريبي مدفوع | لا يحسب التطبيق الضريبة؛ يمكن تسجيل المبلغ يدويًا كمصروف بوصف واضح. |
| AT-18 | إدارة المستخدمين | لا حد ثابت للمستخدمين؛ يمكن إسناد صلاحيات مفردة وإلغاء بعضها. |
| AT-19 | عزل الفروع | لا يرى مستخدم الفرع سجلات فرع آخر بلا صلاحية صريحة. |
| AT-20 | عزل الأنشطة | تمنع قاعدة البيانات وواجهات API قراءة نشاط لبيانات نشاط آخر. |

التغطية الآلية الحالية جزئية. سجل الالتزام والجهاز والخطوات والنتيجة الفعلية قبل إعلان أي اختبار ناجح.
