| عدم تعطيل التطوير بسبب فشل ميزة | معتمد | إذا فشلت اختبارات ميزة، يعالج الخلل ويعاد الاختبار؛ بعد نجاحها يستأنف التسلسل مباشرة. |

## سياسة التنفيذ المستمر

1. اختيار الميزة التالية وفق الأولوية والاعتماديات، مع فحص ما هو موجود قبل كتابة كود جديد.
2. تنفيذ ميزة واحدة أو مجموعة صغيرة مترابطة في كل مرة.
3. تشغيل الاختبارات المستهدفة واختبارات الانحدار المناسبة.
4. عند النجاح، الانتقال مباشرة إلى الميزة التالية دون انتظار موافقة منفصلة.
5. عند الفشل، إصلاح السبب وإعادة الاختبار قبل البناء فوق الخلل.
6. عدم تشغيل بناء Windows أو Android أو إنشاء حزم توزيع لمجرد انتهاء ميزة؛ يؤجل ذلك إلى نقاط التجميع أو الحاجة الفعلية.
7. الحفاظ على القيود: العمل على feature/multi-user-cloud فقط، وعدم الدمج إلى main أو النشر العام أو تغيير بيانات حقيقية دون إذن صريح.

لا تحول بندًا مؤجلًا إلى تنفيذ ضمني. حدث هذا السجل عند ظهور قرار جديد.
