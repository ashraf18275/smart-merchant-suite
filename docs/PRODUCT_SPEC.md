# عدة التاجر الذكي — مواصفات المنتج

**الحالة:** قرارات المنتج المعتمدة؛ لا تعني أن كل وظيفة نُفذت.
**الهدف:** نظام عربي لإدارة التجزئة يعمل محليًا أولًا على Android وWindows، ثم يضيف المزامنة بعد استكمال الأمن والاختبار.

## قرارات معتمدة
- تخزين الأموال بوحدات العملة الصغرى كأعداد صحيحة.
- عملة واحدة قابلة للضبط لكل نشاط. تغييرها بعد وجود معاملات يحتاج ترحيلًا واضحًا.
- لا يوجد احتساب ضريبة أو إنشاء فاتورة ضريبية. أي مبلغ ضريبي مدفوع يسجل يدويًا كمصروف عادي.
- طريقة تكلفة المخزون المستهدفة هي المتوسط المرجح، ويجب توثيقها قبل اعتماد تقارير الربح.
- يمنع المخزون السالب افتراضيًا.
- تدعم المبيعات الدفع الجزئي وتعرض المتبقي، ويرتبط الدين بحساب العميل عند توفره.
- يرتبط المرتجع بالفاتورة الأصلية ويصف حالة الصنف ويسجل حركة عكسية، مع صلاحية اعتماد.
- لا يفرض التطبيق حدًا ثابتًا لعدد المستخدمين. الأدوار والصلاحيات قابلة للتخصيص، بأوصاف عربية لكل إجراء، مع اختيار الكل وإلغاء المفرد.
- تدعم البنية أنشطة وفروعًا متعددة بعزل بياناتها. هذا هدف معماري وليس ميزة جاهزة حاليًا.
- المزامنة بين الأجهزة مؤجلة حتى تنفيذ مرحلتها واختبار حل التعارض.

## الوظائف المستهدفة
النواة المحلية تشمل المنتجات والتصنيفات والوحدات، المخزون والجرد، المبيعات والخصومات والمدفوعات، المصروفات والتقارير، البحث والتصدير والنسخ الاحتياطي والاستعادة. الإدارة الموسعة تشمل العملاء والموردين والديون والباركود والصلاحيات والتدقيق والفروع.

## قواعد الحساب
- المبيعات ليست ربحًا.
- الربح التشغيلي = صافي المبيعات − تكلفة البضاعة المباعة − المصروفات التشغيلية المسجلة. لا توجد معالجة ضريبية آلية.
- لا يعامل شراء المخزون تلقائيًا كمصروف تشغيلي؛ تسجل التكلفة عند البيع وفق سياسة موثقة.
- لا تحذف الفواتير المالية؛ يسجل الإلغاء بحركة عكسية قابلة للتدقيق.
- تفسر الفترات وفق المنطقة الزمنية للنشاط.

## البنية والجاهزية
Flutter للواجهة، SQLite محليًا بترحيلات مرقمة، وفصل الواجهة عن المجال والبيانات والتكاملات. تحفظ الفاتورة والبنود والمخزون والمدفوعات ذريًا. وجود مخطط أو خدمة خلفية لا يعني اتصال الواجهة بها أو جاهزيتها. لا تستخدم بيانات حقيقية قبل مراجعة الأمان والموافقة.
