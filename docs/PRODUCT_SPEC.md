# مواصفات المنتج — عدة التاجر الذكي

**المرحلة:** 1، تثبيت المتطلبات.  
**النوع:** مواصفات معتمدة للبناء على مراحل، وليست ادعاءً بأن كل وظيفة جاهزة.  
**المنتج:** نظام عربي لإدارة متجر أو مجموعة متاجر، يعمل على Windows وAndroid، ويحفظ العمليات محليًا دون اتصال، ثم يزامنها بأمان عند عودة الشبكة.

## 1. المبادئ
- صحة الرصيد المالي والمخزون وسجل التدقيق أهم من سرعة إنهاء العملية.
- لا تعرض وظيفة غير مكتملة على أنها تعمل.
- لا تفقد عملية بيع بسبب انقطاع الإنترنت أو إغلاق التطبيق.
- لا تعدل أو تمحو الأثر المالي أو المخزني بصمت؛ استخدم عكسًا موثقًا.
- قاعدة البيانات والخادم هما مصدر التحقق للصلاحيات، وليس إخفاء الأزرار.
- بيانات كل نشاط معزولة، وصلاحيات الوصول إلى الفروع محددة.
- لا تخزن إلا البيانات اللازمة للعمل، ولا تضع أسرار الخادم في تطبيق المستخدم.

## 2. المستخدمون وحالات الاستخدام
### المالك
ينشئ النشاط والفروع والمخازن، يضبط العملة والمنطقة الزمنية وسياسات التشغيل، يدير الأعضاء والصلاحيات، يراجع سجل العمليات والتقارير والنسخ الاحتياطية.

### الكاشير
يفتح وردية، يبحث أو يمسح باركود منتج، يضيف عدة أصناف إلى السلة، يطبق الخصم إذا سمحت صلاحيته، يقبل وسيلة أو أكثر للدفع، ويحفظ أو يطبع الإيصال. يمكنه تعليق بيع واستكماله عند توفر الصلاحية.

### مسؤول المخزون
يستلم شراءً أو يسجل تحويلًا أو جردًا أو تلفًا، ويعالج فرق الكمية بسبب موثق؛ لا يمحو حركة سابقة.

### المحاسب
يراجع المبيعات والمدفوعات والأرصدة والمصروفات والمردودات والورديات، ويصدر تقارير مسموحًا بها. إجمالي المبيعات لا يسمى ربحًا.

### مدير الفرع
يرى بيانات فرعه ويدير الأعمال التي منحت له صلاحياتها. لا يرى فرعًا آخر افتراضيًا.

## 3. قرارات العمل المعتمدة
1. **الضريبة:** لا يحسب التطبيق ضريبة ولا ينشئ فاتورة ضريبية. إذا أراد المتجر تسجيل مبلغ ضريبي مدفوع، يدخله يدويًا كمصروف عادي مع وصفه. لا توجد ضريبة ضمن إجمالي الفاتورة الآلي.
2. **العملة:** لكل نشاط عملة تشغيل واحدة قابلة للضبط، مخزنة برمزها ودقة وحداتها. لا تجمع تقارير عملتين. تغيير العملة بعد تسجيل حركات مالية يتطلب عملية ترحيل وموافقة صريحة.
3. **الأموال:** تحفظ المبالغ كأعداد صحيحة بوحدات العملة الصغرى، وتوثق قاعدة التقريب. لا تستخدم floating point للحساب المالي.
4. **تكلفة المخزون:** طريقة التكلفة الافتراضية هي المتوسط المرجح المتحرك. يحدّث عند استلام الكميات بتكلفتها، وتنسخ تكلفة الصنف إلى بند البيع وقت إتمامه.
5. **المخزون السالب:** يمنع افتراضيًا لكل مخزن. لا يتجاوز البيع الرصيد إلا إذا غيّر المالك السياسة صراحة وسجل ذلك.
6. **البيع الآجل:** يسمح بالدفع الجزئي. يعرض الرصيد المتبقي ويربطه بعميل محدد؛ لا ينشأ دين مجهول بلا عميل.
7. **المرتجعات:** ترتبط بالفاتورة وبند البيع الأصليين، وتحدد حالة الصنف ومصيره. تتطلب صلاحية مرتجع/اعتماد، وتسجل استرداد المبلغ وحركة المخزون العكسية حسب الحالة.
8. **المستخدمون:** لا يفرض التطبيق حدًا ثابتًا لعدد المستخدمين ولا أدوار موظفين جامدة. يختار المالك صلاحيات كل مستخدم من قائمة مفصلة بأسماء عربية، مع خيار تحديد الكل وإلغاء صلاحيات مفردة. يحتفظ المالك بقدرة الإدارة. حدود مزود الخدمة ليست وعدًا بأن التخزين السحابي بلا حدود.
9. **الفروع:** يدعم النشاط عدة فروع ومخازن. البيانات المشتركة ككتالوج المنتجات تميز عن أرصدة كل مخزن وحركاته. الوصول عبر الفروع يحتاج منحًا صريحًا.
10. **العمل دون شبكة:** تُحفظ العمليات محليًا وتبقى قابلة للمزامنة بأمان. لا يُعلن أن المزامنة تعمل قبل تطبيق واختبار الخادم وتعدد الأجهزة والتعارض.

## 4. نطاق المنتج
### أساسي
تهيئة النشاط، الفروع والمخازن، المنتجات والمتغيرات والباركود والتصنيفات والوحدات، المخزون والاستلام والجرد والتحويلات، نقطة البيع، المدفوعات والمرتجعات، المصروفات، العملاء والموردون، الورديات، التقارير، التصدير والطباعة، المستخدمون والصلاحيات، النسخ الاحتياطي، والمزامنة.

### خارج النسخة الأولى
حساب الضريبة أو إنشاء فواتير ضريبية، مزامنة عمياء بآخر كتابة، متاجر عامة أو خدمات مدفوعة قبل مراجعة التكلفة والخصوصية، وميزات شكلية لا تعمل.

## 5. قواعد الحساب والعمليات
- صافي المبيعات = إجماليات البنود بعد الخصومات المعتمدة ناقص المرتجعات المقبولة؛ لا توجد إضافة ضريبة تلقائية.
- مجمل الربح = صافي المبيعات − تكلفة البضاعة المباعة من تكلفة الصنف المحفوظة في بند الفاتورة.
- صافي التشغيل = مجمل الربح − المصروفات التشغيلية المسجلة، ومنها أي مبلغ اختار المتجر إدخاله يدويًا كمصروف ضريبي.
- استلام المخزون يحدث متوسط التكلفة المرجح بوحدات صحيحة وبقاعدة تقريب موثقة. لا يحدثه أمر شراء غير مستلم.
- البيع يحفظ الفاتورة وبنودها والمدفوعات وحركة كل مخزن في معاملة واحدة.
- المرتجع لا يتجاوز الكمية القابلة للرد من بند الفاتورة، ولا يعيد الصنف للمخزون إلا إذا كانت حالته تسمح بذلك.
- كل عملية مزامنة تحمل معرفًا فريدًا؛ إعادة الإرسال لا تكرر أثرها.

## 6. متطلبات الجودة والتشغيل
- واجهة عربية RTL قابلة للاستخدام بلوحة مفاتيح وماسح باركود، وتدعم أحجام شاشات Windows وAndroid المستهدفة.
- لا يمنع تعطل الطابعة حفظ عملية البيع؛ يظهر فشل الطباعة وتتاح إعادة المحاولة.
- ترحيلات قاعدة البيانات قابلة للتكرار والاختبار والاستعادة.
- سجلات الأخطاء لا تحتوي كلمات مرور أو رموز جلسات أو بيانات عميل حساسة.
- النسخ الاحتياطي قابل للاستعادة على جهاز آخر مع فحص سلامة الملف والمخطط.
- يوضح كل ملف توزيع المنصة والمعمارية ونوع البناء ومتطلبات التشغيل والبصمة.
